# Domain Docs

Messenger uses a single product context.

Before exploring or changing the repository, engineering skills read:

- the root `CONTEXT.md` for canonical domain vocabulary;
- relevant records under `docs/adr/` when that directory exists.

Outputs such as issue titles, specifications, hypotheses and tests use terms as
defined in `CONTEXT.md` and avoid synonyms listed under `_Avoid_`. Missing files
do not block work; domain-modeling creates glossary and ADR artifacts lazily.
